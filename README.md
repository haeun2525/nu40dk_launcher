# NU40DK Launcher

버튼 4개짜리 미니 보드. 하나 누르면 그게 뜬다.

설정이 두 벌 있고, 띄울 때 고른다.

**`config.json` — 버튼 하나에 앱 하나 (기본)**

| 버튼 | GPIO | 여는 것 |
|------|------|---------|
| 1 | 11 | 인스타그램 (웹) |
| 2 | 12 | 터미널 (새 창) |
| 3 | 24 | 팀즈 |
| 4 | 25 | 핀터레스트 (웹) |

**`config.modes.json` — 작업 환경을 통째로**

| 버튼 | 모드 | 하는 일 |
|------|------|---------|
| 1 | 출근 | 팀즈, 아웃룩, 노션 |
| 2 | 코딩 모드 | 터미널(새 창), 클로드, 아두이노 IDE(스케치 열기) |
| 3 | 디자인 모드 | 피그마, 핀터레스트(웹), 인스타그램(웹) |
| 4 | 퇴근 | 위 앱들 + 크롬을 닫고 컨페티 + "얼른 집에 가세요~" |

모드를 만든 이유: 코딩을 시작할 때 실제로 필요한 건 클로드 하나가 아니라
터미널·클로드·아두이노 세 개다. 하나씩 누르면 버튼이 모자란다.

## 구성

저장소는 Arduino 스케치 폴더(`~/Documents/Arduino/nu40dk_launcher`)에 그대로 얹혀 있다.
Arduino IDE가 스케치를 여기서 찾기 때문에, 저장소를 다른 곳에 두면 사본이 둘로 갈라진다.

```
nu40dk_launcher.ino    보드 펌웨어 (버튼 → 시리얼)
host/
  launcher.py          Mac 프로그램 (시리얼 → 앱 열기·닫기)
  farewell.html        퇴근 컨페티 화면
  config.json          버튼 하나에 앱 하나 (기본). 바꾸려면 여기만 고친다
  config.modes.json    출근/코딩/디자인/퇴근 모드. 인자로 골라 쓴다
  run.command          더블클릭 실행
```

역할을 이렇게 나눈 이유: 보드는 "몇 번이 눌렸나"까지만 알린다.
어떤 앱을 여는지는 Mac이 정한다. 매핑을 보드에 넣으면 앱 하나 바꿀 때마다
보드를 다시 구워야 한다.

컨페티는 크롬 **앱 모드**(`--app`) 창으로 띄운다. 탭도 주소창도 없는 전체화면이고,
4.85초 뒤 페이지가 `window.close()`로 스스로 닫는다 — 퇴근인데 창이 남지 않는다.

처음엔 tkinter로 만들었다가 버렸다. **이 맥의 Tk는 창을 만들고도 캔버스를 그리지
못해 흰 화면만 남았다**(`root.update()`에서 멈춤). 설치가 필요 없다는 장점보다
안 그려진다는 결함이 컸다.

**프로토콜** — 보드가 시리얼(115200)로 한 줄씩 보낸다.

```
READY          부팅 완료
BTN1 ~ BTN4    버튼이 눌린 순간 한 번만
```

## 실행

**촬영할 때는 이걸 쓴다.** Ctrl-C 누를 때까지 계속 살아 있다.

```sh
caffeinate -i python3 ~/Documents/Arduino/nu40dk_launcher/host/launcher.py
```

`caffeinate -i`는 그동안 맥이 저절로 잠드는 걸 막는다. 배터리로 촬영하다 화면이
꺼지면 그 순간부터 버튼이 죽는다. Ctrl-C 하면 런처와 잠들기 방지가 같이 풀린다.

잠깐 쓸 거면 `host/run.command` 더블클릭도 된다 (caffeinate는 안 붙는다).

**설정을 골라서 띄울 수도 있다.** 인자로 파일 이름을 주면 그걸 읽는다.

```sh
python3 host/launcher.py                     # config.json — 버튼 하나에 앱 하나 (기본)
python3 host/launcher.py config.modes.json   # 출근/코딩/디자인/퇴근 모드
```

어느 설정으로 떴는지 시작 줄에 파일 이름이 찍힌다. **두 개를 동시에 띄우지 말 것** —
같은 포트를 둘이 나눠 읽어서 버튼이 한쪽에만 들어간다.

보드가 안 꽂혀 있어도 그냥 뜬다. 꽂으면 알아서 붙고, 뽑았다 꽂아도 알아서 다시 붙는다.
포트 이름은 꽂을 때마다 바뀌지만 매번 새로 찾으므로 신경 쓸 것 없다.

**뚜껑을 닫으면 안 된다.** 맥이 잠들면 버튼으로는 못 깨운다 — 이 보드는 시리얼
장치(CDC)라 키보드처럼 맥을 깨울 자격이 없다. 잠든 동안 누른 것은 그냥 사라지고,
깨어난 뒤 밀려서 실행되지도 않는다. 깨우고 나면 런처는 알아서 다시 붙는다.

## 촬영 전 점검

1. 위 명령으로 런처를 띄운다 — "보드 연결됨"이 찍히는지 본다
2. **아두이노 시리얼 모니터는 닫는다.** 열려 있으면 버튼이 씹힌다
3. 퇴근(4번)을 한 번 눌러본다 — macOS가 앱마다 "제어 허용"을 물으면 다 허용한다.
   이걸 미리 안 하면 촬영 때 컨페티 대신 권한 창이 뜬다
4. `config.json`을 고쳤다면 런처를 껐다 켠다. **설정은 시작할 때 한 번만 읽는다**

## 펌웨어 올리기

2026-08-12 업로드·실물 검증 완료. 버튼 4개 모두 `BTN1`~`BTN4`가 나오는 것을 확인했다.
고친 뒤 다시 구울 때만 아래를 쓴다.

```sh
CLI="/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli"
"$CLI" compile --fqbn nucode:nrf52:nu40dk ~/Documents/Arduino/nu40dk_launcher
"$CLI" upload  --fqbn nucode:nrf52:nu40dk -p /dev/cu.usbmodem12301 ~/Documents/Arduino/nu40dk_launcher
```

포트 이름은 꽂을 때마다 바뀐다. `ls /dev/cu.usbmodem*`로 확인하고 넣는다.

Together 보드로 되돌리려면 `~/Documents/Arduino/nu40dk_together`를 같은 방식으로 다시 올리면 된다.

## 설정 바꾸기

설정 파일만 고치고 런처를 다시 실행한다. 펌웨어는 건드릴 필요 없다.
버튼 하나에 앱 하나면 이렇게 짧게 쓴다.

```json
"1": { "name": "인스타그램", "url": "https://www.instagram.com" }
"3": { "name": "팀즈", "app": "Microsoft Teams" }
```

여러 개를 묶거나 닫으려면 `open`/`close`를 쓴다.

```json
"2": {
  "name": "회의 모드",
  "open": [ { "app": "Zoom" }, { "url": "https://notion.so" } ],
  "close": [ "Slack" ],
  "farewell": "회의 시작!"
}
```

- `open` — 적힌 순서대로 0.35초 간격으로 연다. `app`은 `/Applications` 안의 앱 이름, `url`은 기본 브라우저
- `close` — 닫을 앱 이름들. 안 떠 있는 앱은 건드리지 않는다
- `farewell` — 있으면 컨페티 화면에 이 글귀를 띄운다
- `new` — 이미 떠 있는 앱이어도 **새 창**을 띄운다 (아래 참고)
- `file` — 그 앱으로 이 파일을 연다. 새 창이 뜨고 화면에 내용까지 보인다

## 이미 켜져 있는 앱을 '새로 켜지는 것처럼' 보이게 하기

촬영용이다. `open -a`는 이미 떠 있는 앱을 앞으로 끌어올 뿐이라 화면에서는
아무 일도 안 일어난 것처럼 보인다. 세 가지 방법이 있고 앱마다 되는 게 다르다.

| 방법 | 설정 | 권한 | 비고 |
|------|------|------|------|
| 터미널 새 창 | `"app": "Terminal", "new": true` | 불필요 | 돌아가던 창은 그대로. `"command"`로 명령까지 실행 |
| 파일 열기 | `"file": "~/…/foo.ino"` | 불필요 | 창에 내용이 보여서 그림이 좋다 |
| ⌘N 보내기 | 그 밖의 앱 + `"new": true` | **손쉬운 사용 필요** | 아래 참고 |

⌘N은 사람 대신 키를 눌러주는 것이라 macOS가 막는다. 쓰려면
**시스템 설정 → 개인정보 보호와 보안 → 손쉬운 사용**에서 런처를 실행하는 앱
(보통 터미널)을 켜야 한다. 안 켜면 런처가 로그로 알려주고 그냥 넘어간다.

**노션·피그마·팀즈에는 `new`를 넣지 말 것.** 그 앱들의 ⌘N은 창이 아니라
새 문서·새 대화를 만든다. 촬영 때마다 빈 문서가 쌓인다.

앱 이름이 맞는지는 실행하지 않고 확인할 수 있다.

```sh
osascript -e 'id of app "Zoom"'          # 번들 ID가 나오면 정상
open host/farewell.html                  # 컨페티만 따로 보기
```

## 함정

- **시리얼 포트는 한 번에 하나.** Arduino 시리얼 모니터를 열어두면 런처가 못 붙거나,
  붙어도 데이터를 나눠 먹어서 버튼이 씹힌다. 모니터는 닫고 쓴다.
- **같은 버튼 0.8초 재입력은 무시한다** (`launcher.py`의 `COOLDOWN_SEC`).
  손 떨려서 두 번 눌렸을 때 앱이 두 번 뜨는 걸 막는다. 연타를 살리려면 낮춘다.
- **모드가 도는 동안 들어온 입력은 버린다.** 앱 3개를 여는 데 1초 넘게 걸리는데,
  쿨다운 도장을 시작할 때만 찍으면 그 사이 쌓인 신호가 작업이 끝난 뒤 쿨다운을
  통과해 **모드가 통째로 두 번 실행된다**. 실제로 겪은 버그다 — 앱 2개짜리
  '출근'만 멀쩡하고 3개짜리 모드만 겹쳤다. 지금은 작업이 끝난 시점부터 쿨다운을
  다시 세고, 그동안 쌓인 시리얼 입력은 비운다.
- **pyserial을 안 쓴다.** 이 맥에 없어서 termios로 직접 연다. 표준 라이브러리만
  쓰므로 설치할 게 없다 — 촬영 직전에 pip이 막혀 곤란해지는 상황을 피하려는 것.
- **LED는 눌린 버튼만 밝게, 나머지는 아주 약하게 숨쉰다.** 앱이 뜨기까지의
  공백을 눈으로 메우는 용도다. 밝기는 펌웨어의 `IDLE_LEVEL`로 조절한다.
- **퇴근을 처음 누르면 macOS가 "제어를 허용하시겠습니까"를 앱마다 묻는다.**
  촬영 전에 한 번 눌러서 다 허용해두지 않으면, 정작 촬영 때 컨페티 대신
  권한 창이 뜬다. 거절했다면 시스템 설정 → 개인정보 보호 → 자동화에서 켠다.
- **저장 안 한 아두이노 스케치가 있으면 그 앱은 안 닫힌다.** 저장할지 묻는 창이
  뜨고 거기서 멈춘다. 6초(`QUIT_TIMEOUT_SEC`) 기다렸다가 포기하고 다음으로 넘어가므로
  런처가 멈추지는 않는다.
- **퇴근은 크롬도 닫는다.** 열어둔 탭이 같이 닫히니 부담되면 `config.modes.json`의
  퇴근 `close`에서 `"Google Chrome"`을 뺀다. 컨페티도 크롬으로 띄우기 때문에,
  닫은 직후 컨페티 창 하나로 크롬이 다시 뜬다.
- **터미널은 close 목록에 넣지 말 것.** 런처가 거기서 돌고 있으면 퇴근이
  런처 자신을 죽인다.
